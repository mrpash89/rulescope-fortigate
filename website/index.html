See what your FortiGate really allows.

RuleScope reads a FortiGate config backup, or the firewall itself through a read-only API token, and shows what is reachable from the internet, which rules are dead or redundant, where the device is not hardened, and what changed since the last run. It runs on your own machine with nothing but Python.

What it checks

Internet exposure
Every service reachable from outside: port forwards, static NAT, routed inbound rules, admin GUI or SSH on WAN, the SSL-VPN portal. Risky services such as RDP, SMB and databases are called out, and severity depends on who can reach them.
Rule base
Deny rules that never apply, accept rules that can never match, redundant rules with the covering rule named, any-to-any, unrestricted outbound, zero-hit and stale rules, expired schedules.
Device hardening
Telnet and HTTP management, trusted hosts, admins without MFA, the default admin account, lockout and password policy, TLS versions, strong-crypto, SNMP, NTP, HA.
Firmware
FortiOS end-of-support dates, and the CVEs that affect the exact version from the NIST NVD, flagged when CISA lists them as exploited.
Logging and inspection
Accept rules without logging, no central logging, internet-bound rules without IPS, antivirus, DNS filter or application control, expired subscriptions.
VPN
Weak IPsec proposals and DH groups, aggressive mode with a pre-shared key, phase 2 without PFS, SSL-VPN on old TLS or the factory certificate.
Objects
Addresses, groups, services and virtual IPs that nothing references.

On top of the checks, a baseline of {{practices_total}} practices from Fortinet's hardening guide and the CIS FortiGate benchmark is marked pass, partial, fail or not assessed, with the evidence from your configuration. A setting RuleScope could not read never counts as a pass.

Run it on your own firewall

You need Python 3.9 or later and nothing else.

  1. Get RuleScope

    git clone {{repo_url}}.git
cd rulescope-fortigate

  2. Audit a config backup

    Works offline, on a backup you downloaded or one a client sent you.

    python3 -m rulescope audit --config backup.conf --html report.html --cli fix.txt --csv findings.csv

  3. Or read the firewall directly

    With a read-only API token you also get hit counts, licenses and the change log. The certificate fingerprint is checked before the token is sent.

    python3 -m rulescope cert --host 192.0.2.1          # prints the SHA-256 fingerprint
python3 -m rulescope audit --host 192.0.2.1 --token-file ~/.rulescope-token \
    --pin-sha256 FINGERPRINT --html report.html

The README covers the read-only API user, fleet mode, scheduled change tracking and alerts.

Built to run next to production

It never changes a firewall

RuleScope only reads. Fixes come as a script that you review and paste yourself.

Your configuration stays with you

No cloud service, no account, no telemetry. The only optional outbound request is the CVE lookup at the NIST NVD, and it sends a FortiOS version number.

Nothing to install

Python standard library only, with no third-party packages to vet or update.

Configs are treated as hostile

A backup can come from anyone. Names and comments in it cannot become script commands, spreadsheet formulas or markup, and randomized tests check that on every change.

Open source

Apache-2.0. Read the code, run the tests, send a pull request.
